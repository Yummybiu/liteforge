# 统一度量下的 LLM 压缩预算分配：测量、精确求解与预测力验证

**LiteForge 技术报告** · 2026-09 · [代码](https://github.com/Yummybiu/liteforge)（MIT）·
作者：赵元祥（北方工业大学）

## 摘要

部署者在压缩 LLM 时面临一个日常决策：给定比特预算，逐层应该剪枝还是量化？
剪枝文献与量化文献各用各的损失度量，跨方法族的比较历来不公平。本文提出
**统一损失货币**——校准集输出 L2（`L = tr(ΔW·H·ΔWᵀ)`，H=XᵀX 与压缩方法无关），
将剪枝与量化选项组织成逐层菜单，把预算分配形式化为分离式背包并给出**精确
动态规划解**。在 Qwen2.5-0.5B/1.5B/3B 上的实验表明：(1) 预测损失与实际困惑度
在双模型、跨方法族上 **Spearman 秩相关 = 1.000**——排序完美迁移而幅度严重失真，
其机理为上游压缩导致的输入分布漂移；(2) 预算低于方法族质量地板时（约 2.75 bit，
RTN 族），任何分配都会崩溃——**分配器的价值边界先于分配器本身**；(3) SparseGPT
式块级动态重评分在全部三个规模上超过免训练基线 Wanda。全部 55 项离线单测与
40 余组实验记录开源，一键复现。

## 1 引言

LLM 推理成本驱动了两个几乎独立的压缩文献族：以幅值/激活信息删权的剪枝
（Magnitude → Wanda → SparseGPT/OBC）与以低比特表示权重的量化
（RTN → GPTQ → AWQ/SmoothQuant）。它们各自的论文以各自的度量报告收益；
Kuzmin 等（NeurIPS 2023）首次在固定预算下正面比较两者，随后出现联合分配的
探索（DayPQ、BESA、CVPR'25 joint MPQ）。然而据我们所知，**没有一个开源管线
同时提供：跨方法族的统一损失度量、精确（而非启发式）的逐层分配、以及分配
方案在真实困惑度上的预测力验证**。本文以 LiteForge 为载体补齐这条链。

## 2 统一损失货币与逐层菜单

对线性层 y=Wx，压缩引入 ΔW=W−W_c，校准输入 X 上的输出损失

    L = ||X(W−W_c)ᵀ||²_F = tr(ΔW·H·ΔWᵀ),  H = XᵀX

H 与压缩方法无关——一次校准前向（float64 累加、分块采集控显存），剪枝与
量化的全部选项共用。菜单含 8 项：fp16 / W8 / W4 / W3 / W2（g128）/
剪枝 25% / 50% / 75%，有效比特诚实计入 scale 开销（W4g128 = 4.25 bit）。
W8A8 激活量化选项的损失按校准 batch 蒙特卡洛计（激活误差依赖具体 token，
不可用闭式）。

## 3 精确分配与三个策略

预算约束为平均每权重比特：min Σ loss_l(b_l) s.t. Σ d_l·b_l ≤ T·Σ d_l。
菜单比特离散且全模型共享 → 分离式背包可精确求解：维度按 GCD 缩放后
DP 状态数仅数万（0.5B@0.25bit），毫秒级。对照策略：边际价值贪心（文献
常用启发式）与 uniform（部署常用）。应用阶段用 SparseGPT 式动态重评分
执行剪枝、自研 GPTQ 执行量化，随后在完整 test 集上实测 PPL。

## 4 实验

### 4.1 压缩-质量全景（fig_tradeoff.png）

三模型 × 全方法 40 余组真实运行：激活感知是剪枝生死线（50% 稀疏度下
Wanda 25.5 vs Magnitude 485.6，**19 倍**）；分组粒度决定量化质量（W4 下
g128 15.69 vs per-channel 23.99）；自研 GPTQ 在三规模全胜 RTN
（14.13/9.91/8.34，3B 的 W4 距 fp16 无损仅 0.33）；规模效应三点曲线
（50% 剪枝代价 +12.3 → +4.1 → +2.9）。

### 4.2 剪枝方法演化：静态崩塌与动态反超（fig_prune_evolution.png）

静态预选掩码 + 顺序补偿在 0.5B 上 PPL 54.16，**比无补偿的 Wanda 还差一倍**
——机理：H⁻¹ 对角打分集中删除"互相保护的列簇"，簇内保护者彼此删除后
保护失效。改为 SparseGPT 式块级动态重评分后反转为 **17.52 / 11.67 / 9.81**，
三规模全面反超 Wanda（25.52 / 13.34 / 10.89）。

### 4.3 预测力验证：排序迁移，幅度不迁移（fig_prediction.png）

预算批（0.5B/1.5B × 2.75/2.5/2.25 bit × DP/uniform-W4）给出 12 个
（预测损失，实际 PPL）点：**Spearman 秩相关 = 1.000（双模型各 n=6）**——
尽管幅度差 46×至 5000×。排序完美迁移对分配器是充分的（它只消费排序与
边际比较）；幅度失真的机理是 H 在未压缩激活上采集，上游压缩后下游输入
分布漂移、逐层损失被系统性低估——这正是 GPTQ 逐层序贯处理真实输入与
ApiQ 类迭代方法的存在理由，也给出了本文框架的改进方向（序贯重校准）。

### 4.4 方法组件的独立验证

- **SmoothQuant W8A8**（从零，α 网格搜索）：双模型最优 α=0.7
  （非文献默认 0.5），无平滑→最优提升 3.65×/3.98×（fig_alpha.png）；
- **投机解码**（从零）：贪心验证输出与 target 纯贪心逐 token 一致（CPU
  精确算术下 3 种子 × k∈{1,2,8} 单测证明）；bf16 真机出现近平局 argmax
  翻转（fp32 恢复一致），产出公式 tok/fwd = α·k + 1 与实测吻合（4.59 vs 4.57）；
  fp32 下端到端加速 1.96×；无 KV cache 的朴素实现 k=8 加速 0.97×<1——
  被每前向固定开销支配，真部署加速比需 KV cache 实现（未声称）；
- **MMLU-mini 基线**（似然口径）：0.5B 47.6% / 1.5B 57.2%，供压缩模型
  下游对照。

## 5 负结果与分析（同等如实）

- **SGMix 敏感度混合稀疏**：OBS 干跑损失驱动的非均匀稀疏在 0.5B 上劣于
  均匀剪枝（29.5/35.0 vs 25.5）。机理：干跑敏感度度量的是"OBS 打分+补偿"
  下的损失，不迁移到"Wanda 打分+无补偿"；稀疏度-损失曲线强凸。
- **预算下限**：≤2.75 bit 时 RTN 族菜单全体崩溃（651~48 万 PPL），无论
  分配如何。**分配救不了低于方法族地板的预算**——部署者的直觉校准；
  低比特菜单选项应以 GPTQ 口径度量（误差反馈在低比特的边际收益更大）。
- **贪心的规模效应**：0.5B 上贪心与 DP 仅差 0.5%，1.5B 上差距扩大到 5%
  ——组合空间随层数增长，"贪心友好"不是无条件的。

## 6 局限与未来工作

(1) H 的静态采集忽略误差复合——序贯重校准（逐块用已压缩上游的真实输入）
是明确的下一步；(2) 菜单的低比特选项需要 GPTQ 口径重测；(3) 未实现稀疏/
整数推理内核，速度收益的部署口径（vLLM）与质量口径严格分离报告；
(4) CUDA/Triton 内核与多模态压缩在范围之外。
