## 0. 设计目标（对齐求职）

回顾目标岗位与调研结论：
- **主攻**：模型压缩/推理优化算法岗（字节 Seed"模型优化：量化/剪枝/稀疏化/解码加速"、
  腾讯混元量化压缩、智谱 Infra）；
- **面试形式**：七层拷打（为什么→调研→数据→算法细节→自改模块+消融→指标→参数量/速度），
  项目要扛 15-20 分钟连环追问；
- **差异化要求**：不是"调库跑通"，而是每个方法可从零推导、每个结论有本仓库数据、
  每个设计有决策记录。

## 2. 三层架构

```
┌─────────────────────────────────────────────────────────────────┐
│ L3 研究层：压缩预算分配（V2 原创）                                  │
│   lossmeter（统一货币 tr(ΔW·H·ΔWᵀ)）→ allocate（精确 DP/贪心/uniform）│
│   → apply-alloc → 预测 vs 实际 PPL 验证                            │
├─────────────────────────────────────────────────────────────────┤
│ L2 评测层：质量证据链                                               │
│   PPL（滑窗，lm-eval 口径）+ MMLU-mini（似然打分）+ GSM8K（生成式）   │
│   + 损失模型预测力验证 + trade-off/分配地图/报告卡自动生成             │
├─────────────────────────────────────────────────────────────────┤
│ L1 方法层（全部从零实现，统一接口）                                  │
│   剪枝: Magnitude / Wanda / OBC(静态+动态)                         │
│   权重量化: RTN(对称/非对称/分组) / GPTQ(误差反馈)                   │
│   激活量化: SmoothQuant(W8A8, α 网格搜索, 离群迁移)                  │
│   解码加速: 投机解码(draft-target, 贪心验证)                        │
│   部署: vLLM 压测客户端                                             │
└─────────────────────────────────────────────────────────────────┘
横向基建：统一 JSON schema → report 聚合 · 33+ 离线单测 · CI · 决策日志
```

**"厚"的论证**（面试口径）：
1. L1 每个方法都有"推导→实现→测试→数据"四件套，不是调库；
2. L2 评测覆盖语言质量（PPL）+ 知识/推理（MMLU/GSM8K），不是单一指标；
3. L3 是自己的研究问题（前人方法各说各话，这里统一度量+精确分配+验证）；
4. 横向的工程纪律（schema/测试/CI/决策日志）是"能被信任的个人产出"的证据；
5. 与作者两篇在投论文互文但独立（论文方法私有接入接口，不泄漏）。

## 3. 关键技术设计

### 3.1 SmoothQuant W8A8（本日新增，从零）
- 数学：离线等价变换 `s_j = act_max_j^α / w_max_j^(1-α)`，`W' = W·diag(s)`、
  `X' = X·diag(1/s)`——把激活离群值迁移进权重；
- 量化：权重 per-channel 对称 W8，激活 per-token 动态对称 A8（真实推理引擎口径）；
- **α 网格搜索 {0.4–0.9}**，目标 = 统一损失货币下的 W8A8 端到端误差
  （激活量化误差按 batch Monte-Carlo 计入——这是与 weight-only 损失的关键区别）；
- 消融：α 扫描曲线（激活/权重量化难度的跷跷板）、有/无平滑的 W8A8 对照
  （预期：无平滑 W8A8 在离群通道上崩坏——可复现文献结论）。

### 3.2 投机解码（本日新增，从零）
- draft（0.5B）自回归出 k 个 token → target（1.5B）**一次 teacher-forcing 前向
  校验 k+1 个位置** → 贪心接受：与 target argmax 一致则收，遇不一致收 target 的
  token 并截断重 draught；
- 正确性保证（可单测）：贪心投机输出 **恒等于** target 贪心输出——精确性是
  该方法的定理，我们用测试证明；
- 统计：每 target 前向接受 token 数（α 接受率）、 wall-clock 加速比（GPU 实测）、
  k 扫描（k=2/4/8 的接受率-加速 trade-off）。

### 3.3 评测设计（厚度的关键）
- **MMLU-mini**：500 题、4 选 1、**似然打分**（不用生成——log-likelihood 比较
  四个选项，lm-eval 同口径；CPU 可测、GPU 便宜）；按 STEM/人文/社科分桶报
  ——回答"压缩最先伤哪类知识"；
- **GSM8K**：生成式 + 规则判分（已在 rlforge 实现，移植轻量版）；
- **损失模型预测力**：V2 分配的 predicted_total_loss 与实测 ΔPPL 的跨实验
  Spearman 相关——"成本模型可信"本身是被检验的结论。

### 3.4 报告卡（呈现层）
`report_card.py`：扫描 results/*.json → 单文件 Markdown 报告卡（数据表、
trade-off 图、分配地图、α 扫描、投机解码统计、口径声明）——面试时展示的
"一个文件看懂全部"。

## 5. 诚实边界（不做什么，为什么）

- 不实现 CUDA/Triton kernel：算法向岗位不硬性，系统向另有其人——
  仓库里明确声明而非含糊带过（面试官问起即答"这是我刻意画的边界，
  下一阶段在实习里补"）；
- 不做训练感知量化（QAT）与旋转类方法（QuIP#/SpinQuant）：PTQ 免训练范畴
  已足够支撑叙事，文献综述覆盖即可（papers.md）；
- 不承诺多模态压缩实现：列为 roadmap，等论文②出结果后呼应。
