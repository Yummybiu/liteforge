# 极低比特/压缩联合优化四篇精读（QuIP# / AQLM / SpQR / SqueezeLLM）

> 材料来源：arXiv abs 页确认元信息 + arxiv.org/html / ar5iv 全文抓取（2026-09-05）。抓取经小型抽取模型转述，个别表格数字经二次定向核验；未能确认处标注【未获取】。对照本仓库：`liteforge/quant/gptq.py`（自研 GPTQ）、`liteforge/lossmeter.py`（统一损失货币）、`docs/decision_log.md` D21。

## 1. QuIP#（arXiv 2402.04396, ICML 2024）——旋转 + 格点码本 + 微调

**核心思想**：权重离群值（outlier）是低比特崩溃的根源。对 W 和 Hessian 做随机化 Hadamard 变换（RHT）"去相干"（incoherence processing），使权重变成近似球形高斯分布（无离群值）；再用 8 维 E8 格点码本做向量量化；最后微调。注：任务单上写的"HDUQ"一词**未在论文中出现**，对应概念实为 IP-RHT + BlockLDLQ + E8P 三个组件。

**方法细节**：
- 去相干：x → V·S·x，V 为 Hadamard 矩阵、S 为随机 ±1 对角阵；W、H 两侧共轭（Ŵ = Had(diag(S_U)·Had(diag(S_V)Wᵀ)ᵀ)）。理论保证（Lemma 3.1）：变换后幅度集中，界从 QuIP 的 log² 依赖降为线性 log；复杂度 O(n log n)（快速 Walsh-Hadamard，无需浮点乘法）。维度非 2 的幂时分解 n=pq 用 Kronecker 积 H_p⊗H_q（Llama2-70B: 28672=1024×28），无法分解时退化为随机傅里叶变换（略差：2-7B Wiki2 8.30 vs 8.22）。
- E8P 码本：E8 格 = 全整数/全半整数、坐标和为偶数的 8 维向量集合，是 8 维最优球堆积。E8P 为 2-bit、8 维码本，解码用 256×8 查找表 + 符号翻转 + ±1/4 平移，<5 条指令/权重，码本 1KiB 常驻 L1。**码本不学习**（论文实证 K-means 码本更差且难对称化）。3-bit = E8P + 1-bit E8（RVQ 残差级联）；4-bit = E8P 两次。
- BlockLDLQ：GPTQ 的 LDLQ 推广。目标同为 tr((W̃−W)H(W̃−W)ᵀ)，H=E[x xᵀ]；把逐列补偿改为按 g 列一块：Ŵ_k = Q(W_k + (W_{:k−1}−Ŵ_{:k−1})A_k)，Q 为向量量化器。论文未给 g 的数值【未获取】（隐含 = 码本维度 8）。
- 两段微调：①逐块（可并行）微调块内**未量化层**补偿已量化层；②全部量化后调 RMSNorm、符号向量（按实向量优化存 FP16）与 LM head 最小化全模型激活误差。70B 约 50 GPU 时；步数/lr【未获取】。

**与 GPTQ 的关系**：QuIP# 保留了误差反馈的骨架（BlockLDLQ 就是 LDLQ 的分块版），但在反馈之外加了两层"事前防御"——旋转让误差在进入量化器之前就变小，格点码本让同样的残差落到更近的重建点上；微调则负责"事后补救"。对照我们的 `_gptq_layer`：若插入旋转，改动点在 collect H 之后、damp_inverse 之前对 W 与 H 同步共轭，量化循环本身不变。

**默认超参**：2/3/4 bit，Hessian 用 RedPajama 1T 的 6144 条原生上下文序列（Llama1: 2048 / Llama2: 4096）。

**关键数字**（Wiki2）：2-bit 2048ctx：L1-7B 6.86 / L1-13B 5.97 / L2-70B 4.16（对比 OmniQuant 15.5/13.2/7.81）；4096ctx L2-7B/13B/70B = 6.19/5.35/3.91。消融（2-bit L2-7B, 2048ctx）：全量 6.66，去微调 8.22，去微调+去 E8（退回 1 维半整数格）12.3。3-bit Llama2 优于"理论无损 4-bit"（首次）。4090 上 2-bit 70B 32.7 tok/s。

## 2. AQLM（arXiv 2401.06118, ICML 2024）——加性多码本 + 块级联合优化 + 微调

**核心思想**：把"每组权重近端一个量化格"换成"每组权重 = M 个码本码字之和"（加性量化，源自检索文献 PQ），目标仍是输入自适应的层输出误差 ‖WX−ŴX‖²₂，码本与码字在 transformer 块内联合优化，可选端到端蒸馏微调。2-bit 段当时 Pareto 最优。

**方法细节**：
- 参数化：行按组大小 g=8 切分，每组表示为 Σₘ Cₘ bᵢⱼₘ（M 个码本各贡献一个码字，码本条目数 2^B）；另存逐行 scale（初始化 sᵢ=‖Wᵢ‖₂）。
- 求码：目标改写为全连接离散 MRF 的 MAP 推断——一元势 ⟨W,Cₘbₘ⟩_XXᵀ、二元势 ⟨Cᵢbᵢ,Cⱼbⱼ⟩_XXᵀ（XXᵀ 预计算）；用 beam search（维护 top-k 码配置，逐步试 2^B·k 个替换，全 d_out 并行），初始化用残差 K-means（消融：随机初始化需多得多迭代）。
- 三阶段：①残差 K-means 初始化；②码冻结，Adam 全批更新码本（100 步，lr 1e-4）；③块内 cohesion——量化完块内 4-8 个线性层后，码冻结，调码本/scale/RMSNorm 匹配**量化前**块输出，占总校准时间 10-30%。
- 端到端微调（★标注）：FP 教师对学生的 KL 蒸馏，RedPajama 4-16M token，Adam lr 1e-5、无 weight decay、1 epoch。消融（7B@2.02b，Wiki2/C4）：不调 8.18/10.59 → 只调 AQ 参数 6.92/8.85 → 全调 6.93/8.84：**码本承载 >99% 可调容量**。注：社区流传的"+1B token LoRA"变体是代码库后续版本，v4 正文未获取。

**与 GPTQ 的关系**：AQLM 是四篇中最"重"的一条路线——它放弃了顺序反馈（beam search 是对整组码的全局搜索，天然不需要"从左到右传误差"），把全部赌注押在码本表达力与联合优化上。对我们 lossmeter 的启发在目标函数而非算法：它的一元/二元势展开恰好就是 tr(ΔW·H·ΔWᵀ) 在"ΔW 来自多码本之和"约束下的展开，说明统一货币可以原封不动地为加性量化计价。

**默认超参**：2-bit = 单码本 2^15–2^16 条目、g=8（16-bit 码索引）；3-bit = 2 码本×2^12、g=8；4-bit = 2 码本×2^15–2^16、g=8。校准 RedPajama 8M token，seq 4096（Mixtral 8192）。成本：7B 约 1×A100 一天；70B 约 3-4 天×8 卡。

**关键数字**（Llama2, Wiki2/zero-shot）：2-bit：7B 6.59/57.28（QuIP# 8.22）、13B 5.60、70B 3.94；蒸馏后 6.14/5.33/3.83，与 QuIP# 打平。3-bit 7B 5.46 vs GPTQ 8.06。帕累托拐点 ≈2.5 bit；13B@2.76b（4.94）压过未压缩 7B（5.12）。

## 3. SpQR（arXiv 2306.03078）——异常值双层编码的 GPTQ 增强

**核心思想**：在 GPTQ 顺序量化之上，把"量化误差×输入二阶范数"最大的少数列（<1%）摘出来存 16-bit，其余权重 3-4 bit 分组量化——宣称近无损（相对 fp16 困惑度损失 <1%）。

**方法细节**：
- 敏感度判据：逐列打分 s_i = ‖(W_i − Q(W)_i)·diag(XᵀX)_i‖，即该列量化误差按输入能量加权（OBS 打分家族，与本项目 OBC 的 w²/(H⁻¹)ⱼⱼ 同源但作用于"量化残差"）；取分位阈值 τ，异常值占比 <1%。
- 异常值处理：主矩阵仍走 GPTQ 顺序补偿（异常值列也参与补偿路径），**存入稀疏矩阵的是补偿后的权重值**；组大小 16。
- 元数据双重量化：每组的 scale/zero 不存 FP16，而是各自再量化为 bs=bz=3 bit，超组 β1=β2=16；总比特 b̄ = b_w + (bs+bz)/β1 + 64/(β1β2) + 32·r_o（3-bit 统计量 + r_o=0.004 时 ≈3.63 bit）。
- act_order：按 diag(H⁻¹) 重排列处理顺序。论文观察（与 D21 直接相关）：GPTQ 顺序量化中"**最右侧的列累积最多误差**"，随机置换可消除该效应；但 65B 消融中收益很小（3-bit statistics：C4 5.73 → 无排序 5.76，Wiki2 均 3.74）。

**与 GPTQ 的关系**：SpQR 对 GPTQ 的改动最小、收益却很实在，是"在现有实现上加一个组件"的样板：误差反馈照旧，只是把反馈救不动的列（打分高的列）直接请出量化矩阵。我们的 `GPTQQuantizer.quantize_` 已经算好了 H⁻¹ 与 U，异常值打分所需的 (W−Q(W)) 与 diag(H) 都是现成中间量，无需重新前向。

**默认超参**：主权重 b_w=3（压缩档）/4（近无损档），组 16，β1=β2=16，bs=bz=3，异常值 <1%。

**关键数字**（Llama-1 65B，Wiki2/C4/PTB，经二次核验）：fp16 3.53/5.62/6.91；RTN 4-bit 3.87/5.85/7.17；GPTQ 4-bit 3.83/5.80/7.07；SpQR 压缩档 3.90 bit → 3.68/5.70/6.99；近无损档 4.71 bit → 3.57/5.64/6.93。消融（65B，无异常值）：3-bit statistics 3.74@3.63bit vs 16-bit statistics 3.84@3.67bit（3-bit 统计量本身是重要收益）。33B 可单卡 24GB 运行（摘要）。7B/13B/Falcon 具体表值【未获取】；Llama-2 70B 表在不同版本抓取中不一致，按最后核验版本论文不含该表【未获取】。

## 4. SqueezeLLM（arXiv 2306.07629, ICML 2024）——敏感度加权非均匀量化 + 稠疏分解

**核心思想**：推理是访存瓶颈且反量化后算术在 FP16，均匀量化的"整数运算高效"毫无用处 → 放弃均匀格，直接学**非均匀码本**：用二阶信息（对角 Fisher）加权的 1-D k-means 求每个输出通道的码字；再把不可量化的离群/高敏感权重摘出存 FP16 稀疏格式。

**方法细节**：
- 目标：min Σᵢ F_ii(wᵢ−Q(wᵢ))²，Hessian 用经验 Fisher 对角近似 F ≃ (1/|D|)Σ g_d g_dᵀ 的对角（逐样本梯度，65B 仅 2.5 分钟）；**OBD 口径**（最小化最终输出扰动）而非 OBS/层内重构口径，附录 D.4 称 OBD 比层内目标好约 0.3 PPL。求解 = 敏感度加权 k-means，每输出通道一个 2^b 条目查找表（LUT），反量化后 FP16 计算。
- Dense-and-Sparse：W = D + S，S = 分布两端分位阈值外的权重（0.4% 离群值）+ 按敏感度挑的 0.05% 高敏感值，共 ~0.45%，FP16 + CSR 存储；稠密部分动态范围压缩约 10×，非均匀量化才生效。推理 = 稠密 LUT 核 + 稀疏核重叠。
- **无 GPTQ 式误差反馈**：不逐列补偿，靠"码本适配分布 + 摘走难点权重"静态防误差。

**与 GPTQ 的关系**：SqueezeLLM 是唯一与误差反馈路线正面分庭抗礼的一篇，其论证值得记下：推理是访存受限、反量化后运算在 FP16，均匀量化唯一的实惠（整数算术）根本用不上，那就不如把量化格完全换成数据驱动的码本。这解释了它为什么能在不引入任何顺序补偿的情况下压过 GPTQ——但代价是逐通道 LUT 的码本存储（8 个 FP16 码字/通道，b_eff 记账时不可忽略，约 8×16/d_in 的摊销）。

**默认超参**：3-bit（k=8 码字/通道）；稀疏 0%（纯稠密）或 0.45%；校准 100 条样本（Vicuna 训练集/C4），seq 2048，10 条已接近饱和。

**关键数字**（Llama-1 7B，Wiki2/C4）：fp16 5.68/7.08；RTN 25.61/28.26；GPTQ(g128) 7.55/9.55；AWQ(g128, 3.24b) 6.44/7.90；SqueezeLLM 3.02b 6.32/7.75；+0.45% 稀疏（3.24b）**6.13/7.56**。13B/30B/65B +0.45% Wiki2 = 5.45/4.44/3.88。消融链（7B, C4）：均匀 28.26 → 非均匀+敏感度 7.75 → +0.05% 敏感值 7.67 → +离群值 7.56（Llama2-7B 上非均匀化单项 26.58→5.96，是主导因素）。A6000 加速 1.5-2.4×。

## 5. 方法谱系：GPTQ 之上各加了什么

四篇共享同一母题——Hessian 加权目标 tr(ΔW·H·ΔWᵀ)（H=XᵀX），分歧在"如何让 ΔW 在低比特下仍然小"：

```
                 GPTQ (ICLR'23)：顺序误差反馈（LDLQ 补偿）
                 目标 tr(ΔW H ΔWᵀ)，逐列量化把残差传给未量化列
        ┌───────────────┬──────────────────┐
        │               │                  │
   ①整形输入侧      ②换量化格           ③预算再分配
   QuIP#            QuIP#/AQLM         SpQR / SqueezeLLM
   RHT 旋转去       E8P 格点码本(VQ)   敏感度打分摘异常值
   相干(离群值消失)  AQLM 加性多码本     (16bit/FP16 稀疏)
        │          (码字求和,beam search)
        │               │                  │
        └───────┬───────┘                  │
            ④训练后修正                      │
   QuIP#: 块内补偿微调+全模型调Norm/符号向量  SqueezeLLM: 无反馈
   AQLM:  块内 cohesion + KL 蒸馏           (加权 k-means 静态防误差)
   SpQR:  (无；靠异常值摘除+act_order)
```

- SpQR 离 GPTQ 最近：原封保留顺序补偿，外挂"异常值分离 + 元数据双重量化 + act_order"。
- SqueezeLLM 反向：**拒绝**误差反馈，用对角二阶信息改码本本身（非均匀）+ 摘权重（稠疏分解），OBD 口径。
- QuIP# 保留反馈并推广（BlockLDLQ），但把重心移到预处理（旋转）与量化格（E8P），微调兜底。
- AQLM 保留 H 加权目标但**不用顺序反馈**：MRF-MAP/beam search 全局求码，靠码本表达力与块级联合优化取胜。

## 6. 对 D21 的印证与解法对照

**D21-①（H 在未压缩激活上采集 → 误差复合 → 逐层损失被系统性低估）**：四篇各自给出解法，分两类——
- *让模型适配漂移*（≈ ApiQ 迭代修正思路）：QuIP# 块内"先补偿已量化层"微调 + 全模型后处理（调 RMSNorm/符号向量/LM head）；AQLM 块内 cohesion（匹配量化前块输出）+ 端到端 KL 蒸馏。注意它们也不重采 H，而是把修正交给可训练参数。
- *从源头减小每层 ΔW*：SpQR/SqueezeLLM 把"量化误差×二阶范数"大的权重摘出（16-bit/FP16），下游漂移源头变小。
- 互文：我们实测"排序完美迁移（ρ=1.000）而幅度低估 46×"，与 SpQR 消融中 act_order（精细排序型技巧）收益极小（C4 +0.03）一致——**二阶/排序层面的精细化不是瓶颈，方法族地板才是**。lossmeter 一次采 H 全菜单共用的"低估"缺陷，作为分配器信号可容忍；若要修幅度，优先级是序贯重校准 > 敏感度精修。

**D21-②（RTN 菜单低比特段崩溃，"分配救不了低于方法族地板的预算"）**：直接被数据印证——同为 3-bit Llama-7B：RTN 25.61 / GPTQ 7.55 / SqueezeLLM 6.32，同预算差 4 倍；2-bit 段 GPTQ 也崩，而 AQLM 6.59 / QuIP# 6.66-6.86 说明 2-bit 并非不可用，是我们的菜单里**没有相应组件**。四篇的全部贡献都可以概括为"抬方法族地板"的四个正交旋钮：旋转、码本、异常值分离、微调。

## 7. 可借鉴清单（标工作量；★=建议进菜单/预算口径）

**SpQR（性价比最高，全部可用现有 H/U/Hinv_diag）**
1. ★敏感度异常值分离：列打分 = 量化误差×diag(H)，top ~0.5-1% 存 FP16。小（0.5-1 天）。菜单选项 `w3+sp0.5%`；与我们 OBC 打分同构，lossmeter 加一个选项即可。参考收益：SqueezeLLM 3-bit 7.75→7.56、SpQR 3.74（65B 近无损）。
2. ★元数据双重量化：scale/zero 本身 3-bit 再量化（β1=β2=16）。小（~0.5 天，改 group_params + `effective_bits_quant` 记账：分组开销 32/g → 约 (6+64/16)/(16·16)·16≈0.19/g 级别，所有分组选项 b_eff 直降）。
3. act_order（按 diag(H⁻¹) 重排列）。小（~0.5 天）。低比特/小模型收益更大，65B 上很小；兼作 D21 排序叙事的对照实验。
4. 存"补偿后"异常值而非原始值（随 1 附带）。极小。

**SqueezeLLM**
1. ★敏感度加权 k-means 非均匀量化（逐通道 LUT，k=2^b）。中（1-2 天）。菜单选项 `w3-lut`：把 W3 RTN→W3 非均匀的最便宜路径，与 RTN 同构、无需顺序反馈；可先用 H 对角（Σx²）作 Fisher 对角的一阶代理（需在文档标注口径差异）。参考收益：单项 26.58→5.96（Llama2-7B 3-bit）。
2. ★Dense-and-Sparse 分解（0.4% 离群 + 0.05% 敏感 → FP16/CSR，b_eff 仅 +0.07）。小-中（1 天，与 SpQR-1 共用摘除机制）。菜单 `w3-ns`。
3. OBD vs 层内重构口径对照实验（论文称差 ~0.3 PPL）。小（0.5 天）：直接校准我们统一货币（层输出 L2，OBS 口径）在低比特段是否失真，服务 D21-①。
4. 校准集敏感性极低（10 条 ≈ 100 条）。信息项：可省我们的 H 采集成本。

**QuIP#**
1. ★RHT 旋转预处理器：W、H 同步共轭（W′=W·RS，H′=RSᵀH·RS，RS=diag(±1)·WHT）。中（1-2 天）。菜单选项 `w2/w3-rot`：旋转后连 RTN 都接近均匀分布，是抬 W2/W3 地板的最通用组件。注意：损失度量口径（lossmeter）极易实现；真机部署需在相邻层间做等价激活旋转（改图），工作量另计——诚实标注两口径差异。
2. BlockLDLQ（逐列→按 g 列块状补偿）。小-中（~1 天，复用现有 Cholesky U），是接入 VQ 的前置改造。
3. E8P 格点码本 2-bit VQ（+RVQ 扩展）。大（3-5 天：最近格点搜索 + 查表解码 + b_eff 记账支持 8 维/组）。菜单选项 `w2-vq`——2-bit 段最强选项族，直接回应"预算下限"发现（QuIP# 2-bit 6.66 vs 我们菜单当前 651+）。
4. 块级/全模型微调（Adam 调 RMSNorm、LM head 等未量化参数）。中（~1 天管线 + 算力）；作为所有低比特选项的全局后处理，不新增菜单项。

**AQLM**
1. ★加性量化求解器（残差 K-means 初始化 + XXᵀ 加权 beam search 求码）。大（3-5 天）。菜单 `w2-aq/w3-aq`：2-bit 段开源最强（7B 6.59）。
2. ★块内 cohesion 微调（码冻结，调码本/scale/RMSNorm 匹配量化前块输出）。中（1-2 天）。同时是 D21-① 误差复合的修正组件。
3. 端到端 KL 蒸馏微调（RedPajama 4-16M token，lr 1e-5）。中-大（管线 1 天 + 训练算力）。消融显示码本承载 >99% 收益，故优先调码本而非 Norm。
4. "大码本"配置设计经验（2-bit 用单码本 2^15–2^16、g=8 而非多小码本）。信息项，指导 1 的参数化。

**落地次序建议**：SpQR-1/2 + SqueezeLLM-1/2（合计 ~3 天，全部进菜单、直接抬高 2-3 bit 段地板与 b_eff 记账精度）→ QuIP#-1（旋转）→ AQLM-2/QuIP#-4（微调）→ 格点/加性码本（最大收益，最大工作量）。
