## 1. Wanda（Sun, Liu, Bair, Kolter — ICLR 2024）

### 1.1 核心思想
LLM 剪枝不必重建权重：删除 `score_ij = |W_ij| · ‖X_j‖₂` 最小的权重即可。直觉来自 LLM 的"激活幅度异常值"（emergent magnitude features）：权重幅度的离群值总是落在激活幅度也大的通道上，所以**幅度必须用对应输入激活范数加权**才是有效的删除判据。这是 SparseGPT 打分 `w²/(H⁻¹)_jj` 在"只保留 Hessian 对角、去掉补偿"时的平方根形式——用可忽略的代价换掉整个二阶重建。

### 1.2 可复现级细节
- **度量与分组**：对每个输出行 i 独立做 top-k（per-output 比较），删除该行 score 最小的 s% 权重。消融（LLaMA-7B, 50%, WikiText PPL）显示 per-output 对 LLM 是关键选择：Wanda metric 在 (output,1) 分组下 7.26，而逐层全局排序（layer）7.95、(input,128) 8.12；图像分类器（ConvNeXt/DeiT）上该趋势反转（逐层更好），是 LLM 特有现象。
- **激活范数**：`X.norm(p=2, dim=0)`，即第 j 列输入在全部 N×L 个 token 上的平方和开根。论文只有定性陈述"ℓ2 优于 ℓ1/ℓ∞"，**无数字消融表（未获取）**。
- **稀疏度施加**：所有线性层统一 s%（跳过 embedding 与 lm_head，二者合计约 1% 参数）。
- **校准**：C4 训练集 128 条序列（沿用 SparseGPT 设置；序列长度数值论文未写明，**未获取**）。采样数消融（WikiText, 50%）：LLaMA-7B 用 1 条样本 PPL 7.46、16 条 7.27、128 条 7.26、1024 条 7.25——一阶统计量对样本数极不敏感；对照 SparseGPT 用 1 条样本会崩到 10.22。
- **执行方式**：单次前向、逐层顺序剪枝，后续层在被剪过的前层输出上重新采集激活（"sequential"）。此细节在 50% 稀疏下影响很小（7.26→7.32），70% 时巨大（84.50→29.65）。
- **N:M 变体**：在每 M 个连续权重的组内用同一度量比大小（2:4、4:8），仍是 per-output。LLaMA WikiText PPL：

| 方法（权重更新） | 2:4 @7B | 2:4 @13B | 2:4 @65B | 4:8 @7B |
|---|---|---|---|---|
| Magnitude（无） | 42.13 | 18.37 | 7.11 | 16.84 |
| SparseGPT（有） | 11.00 | 9.11 | 6.28 | 8.61 |
| Wanda（无） | 11.53 | 9.58 | 6.25 | 8.57 |

  Wanda 2:4 实测在 LLaMA-65B 上 matmul 提速约 1.6×。**注意：论文中不存在"注意力头维度 sparsity"或 group-size K(4/8/16) 变体**——全文核实仅在相关工作里引用了 Deja Vu、Bansal et al.、Voita et al.（头/通道稀疏），属"未获取（论文中未实现）"。用户常说的"组内变体"即上述 N:M。
- **主结果**（WikiText PPL，50%）：LLaMA-7B dense 5.68 / magnitude 17.29 / SparseGPT 7.22 / Wanda 7.26；13B：5.09 / 20.21 / 6.21 / 6.15。零样本均值（7 数据集）7B：dense 59.99 / magnitude 46.94 / SparseGPT 54.94 / Wanda 54.21。
- **可选恢复**：LoRA r=8 于 q/v 投影（+0.06% 参数），1 卡 12h：零样本 54.21→58.15（dense 59.99）；全参 FT 4 卡 3 天 → 更近 dense。
- **速度**：仅打分阶段，LLaMA-65B 上 Wanda 5.6s vs SparseGPT 1353.4s（约 300×）。
- **鲁棒性**：5 个随机种子下 Wanda 7.25±0.01，SparseGPT 7.25±0.03。

### 1.3 我们实现未覆盖的细节
对照 `wanda.py`：(a) 我们用 RMS（x_sum/n 开根）替代论文的列 ℓ2 范数——只差一个逐层常数标量，行内 top-k 排序**完全等价**；(b) 我们一次性采集激活（原始前向），未做论文的"逐层剪完重采前向"顺序模式——50% 下代价约 +0.06 PPL，70%+ 时必须补；(c) N:M 已支持（`group_2to4_mask`），4:8 对照未跑；(d) 采样数消融、多种子方差、LoRA 恢复臂未实现。

## 2. LLM-Pruner（Ma, Fang, Wang — NeurIPS 2023）

### 2.1 核心思想
把 LLM 当作有向图做**结构化剪枝**：先用依赖规则找出必须同生同灭的"耦合结构组"，用梯度信息对组打分，整组删除；再用 LoRA 快速恢复。目标是任务无关压缩（保留多任务与生成能力），不依赖原始预训练语料。

### 2.2 耦合结构分析（我们完全没有的能力）
- 依赖规则：若 N_j ∈ Out(N_i) 且 N_j 入度为 1，则 N_j 依赖 N_i（反向对称）。从每个神经元出发闭包得剪枝组。
- LLaMA 上形成两类组：**Group Type B**（Block 策略的注意力部分）= 一个注意力头 + 它在 Q/K/V 中的输出神经元 + o_proj 对应的输入神经元——三者必须整组删；**Group Type C**（Channel 策略）= Q/K/V 的输入维 ↔ o_proj 的输出维。FFN 侧每个隐维（LLaMA-7B 为 11008 个）各成一组。
- 关键实证：去掉耦合分析直接删会"链式断路"——无依赖处理时未调优 PPL 爆炸到 68378。论文未涉及 GQA（对象均为 MHA）；**GQA 下 K/V 头共享的耦合处理：未获取（论文未讨论）**。

### 2.3 重要性估计
- 校准：10 条样本 × 128 token（LLaMA/Vicuna 用 Bookcorpus，ChatGLM 用 DailyDialog），下一词预测损失。
- 向量级（对整个剪枝组 W_i）：`I = |L(W_i) − L(W_i=0)| ≈ |(∂L/∂W_i)·W_i − ½W_iᵀHW_i + O(‖W_i‖³)|`。保留一阶项的理由：校准分布 ≠ 预训练分布，梯度项不为 0。
- 元素级（Fisher 近似 H 对角）：`I ≈ |∂L/∂W^k · W^k − ½Σ_j (∂L(D_j)/∂W^k · W^k)² + O(‖W^k‖³)|`。Element¹ 只留一阶项，Element² 加二阶项（注意命名是 Taylor 阶数，不是 L1/L2 范数）。组内聚合取 Sum 最稳。

### 2.4 剪枝比例与结构保护
- 默认 20% 参数量（也测 50%；ChatGLM 只做 10%）。
- **Block 策略**：保护首 3 层与最后 1 层（"改动这些层显著影响模型"），20% 目标换算成"Layer 5 到 Layer 30 内剪 25% 组"；50% 时在 Layer 4–30 剪 60%。embedding 保留。
- **Channel 策略**：所有层统一处理（含 embedding，仅 Q/K/V 剪输入维、o_proj 剪输出维），论文自评这是弱点——被迫剪首末层。局部（逐模块）排序略优于全局。
- 产物：LLaMA-7B（6.74B）→ 5.39B（Channel 20%）/ 5.42B（Block 20%）；50% → 3.37B/3.35B。MACs 424.02G→339.60G，显存 12884→10376 MiB，A5000 64-token 延迟 69.32s→58.55s。

### 2.5 LoRA 恢复协议（可直接照抄的超参）
LoRA 加在**所有线性层**（ΔW=PQ，训后重参数化不增推理尺寸）；rank=8；lr 1e-4，100 warmup；batch 64 或 128；AdamW；2 epochs（更久过拟合）；清洗 Alpaca 约 50K 样本；24GB 单卡约 3h（RTX4090 约 2.5h）。**LoRA alpha：未获取（论文未给出）**。

### 2.6 主结果（论文自有评测口径，其 dense 基线 PPL 与 SparseGPT 系不同管线，不可直接横比）
LLaMA-7B dense：WikiText2 12.62，零样本均值 63.25。20% 剪后未调优：PPL 19.09、保留 89.8%；+LoRA（Element²）：PPL 17.37、保留 94.97%（60.07）。50% 剪枝急剧退化（调优后均值 48.69），换 2.59M 样本恢复到 62.36（−0.89%）。剪出的 3.4B 与 StableLM-3B 对比：50.30 vs 45.84。

### 2.7 我们实现未覆盖的细节
耦合组建模、Taylor 梯度重要性、结构保护先验、LoRA 恢复训练及"压缩-延迟"联合报告。

## 3. Sheared-LLaMA（Xia, Gao, Zeng, Chen — ICLR 2024 / COLM）

### 3.1 核心思想
不追求稀疏度，而是**把大模型剪成指定目标形状**（层数、头数、隐维、FFN 中间维全可调），把"逐层敏感度分配"替换为"端到端可学习掩码 + 拉格朗日形状约束"，再用**域均衡的动态批量加载**做 50B token 继续预训练。LLaMA2-7B → 1.3B/2.7B，质量超同尺寸从零训练模型（Pythia/INCITE/OpenLLaMA/TinyLlama），算力仅为从零训练的 3%（论文 Figure 1：2.7B 用 OpenLLaMA-3B-v2 预算的 1/32）。

### 3.2 Targeted structured pruning 公式
- 四类掩码：z^layer、z^hidden、z^head（每层）、z^int（每层），服从 hard concrete 分布（β=0.83, ζ=1.1, γ=−0.1）。
- 形状约束用（线性, 二次）拉格朗日对，如头数约束：`L̃ = λ(Σz−H_T) + φ(Σz−H_T)²`；总目标 `min_{θ,z} max_{λ,φ} L(θ,z) + Σ L̃^head + Σ L̃^int + L̃^layer + L̃^hidden`（Platt & Barr min-max）。
- 掩码乘在**输出**上（头输出/FFN 中间输出/层输出/隐维输出），数学上等价删参数；训练后阈值二值化，未收敛到 0/1 的掩码值直接吸收进参数。
- 训练设置：LR(θ)=1e-4、LR(z,λ,φ)=1.0，warmup 10%，batch 131K token，3,200 步（≈0.4B token），8×A100；吞吐 15K token/s。
- 目标形状抄现成模型：1.3B 对齐 Pythia-1.4B（24 层、hidden 2048、16 头、FFN 5504；从 32 层删 8 层），2.7B 对齐 INCITE-3B（32 层全保留、hidden 2560、20 头、FFN 6912）；头数 = 目标隐维 ÷ 源头维 128。

### 3.3 动态批量加载（数据维度的"再分配"）
对 k 个域，每 m 步算各域验证损失超额 `Δ_t[i] = max(ℓ_t[i]−ℓ_ref[i], 0)`，指数上升更新采样权重 `w_t ∝ w_{t−m}·exp(Δ_t)`（承 DoReMi）。参考损失用 scaling law `L = E + A/N^α + B/D^β` 对 LLaMA2-7B/13B/70B 逐域拟合（<4 A100·h）；1.3B 示例：C4 2.125 / CC 1.964 / Book 2.139 / Wiki 1.759。m=50（剪枝）/400（CT）。

### 3.4 结果与成本
- 下游 11 任务平均：2.7B 得 56.7，优于 OpenLLaMA-3B-v2 55.7、INCITE-3B 54.7、Pythia-2.8B 52.5、OPT-2.7B 51.4；1.3B 得 51.0，优于 TinyLlama-1.1B 50.0、Pythia-1.4B 48.9。
- **剪枝 vs 继续预训练的消融（1.3B）**：仅剪 0.2B token PPL 12.99 → CT 后 7.46；0.4B：10.29→7.32；1.6B：8.04→7.08。恢复训练贡献约 5.5–6.2 PPL，是结构化剪枝的**必要组成部分**。
- 与 LLM-Pruner 同口径对比（LLaMA2-7B→2.7B 档）：PPL 6.85 vs 7.09。
- 指令微调后 GPT-4 判定胜率对全部基线占优（具体数值在图中，**未获取**）。总 GPU 小时未给出，仅吞吐（CT 145K/77K token/s × 16 GPU）。

## 4. 非结构化 vs 结构化：真实取舍

以我们 `results/table.md`（Qwen2.5 系列，WikiText-2 PPL，稠密推理口径）+ 三篇论文的数字：

| 档位 | 质量代价 | 真实加速 | 恢复成本 |
|---|---|---|---|
| 非结构化 50%（Wanda/OBC，我们的路线） | 0.5B：13.21→25.52；1.5B：9.26→13.34；3B：8.01→10.89 | **无**（稠密 kernel 无收益；需 2:4 或稀疏库才兑现） | 零（可选 LoRA 12h/7B） |
| 2:4 半结构化 | 0.5B：25.52→70.14（见第 6 节） | ~1.6× matmul（论文 65B 实测；Ampere+） | SparseGPT 式权重更新可大幅回收（文献 11.53 vs 我们 70.14 的差距主要是这个） |
| 结构化 20%（LLM-Pruner） | 保留 ~90%（不调优）/ ~95%（+LoRA） | 任意 GPU：MACs −20%，延迟 −15.6%（69.32→58.55s） | LoRA：50K 样本、2 epoch、24GB 单卡 ~3h |
| 结构化 50%（LLM-Pruner） | 崩（均值 48.69，−23%） | MACs 约减半 | 2.59M 样本才回到 −0.89% |
| 形状剪枝 + 50B CT（Sheared） | 反超同尺寸从零训练 | 形状级（层数/宽度真正变小） | 50B token + 16×A100 天级；剪后 12.99→CT 7.46 |

三条硬结论：(1) **恢复成本随结构化程度单调上升**（0 → LoRA 小时级 → 50B token），结构化剪枝的质量必须连恢复一起评估；(2) 非结构化 50% 在 0.5B–3B 区间质量最好（OBC 还能把 0.5B 从 25.52 压到 17.52），但稠密 kernel 无速度收益——这正是我们用 vLLM 单测吞吐的原因；(3) 结构化的本质优势是**全硬件可兑现的加速**与显存/带宽同降，代价是恢复训练预算。

## 5. 可借鉴设计清单（含工作量；★ = 直接针对 SGMix 负结果）

### 来自 Wanda
1. ★**把 SGMix 敏感度源从 OBS 干跑换成一阶统计量**（~0.5 天）。Wanda 证明一阶量 1 条样本即达 7.46（128 条 7.26），且 300× 便宜；我们的 OBS 干跑（`obc.py::score_dry`）需逐层 damp+求逆，且其静态打分缺陷我们自己在 `_sequential_zero_dynamic` 注释里已论证过。
2. **通道级保护替代层级预算转移**（~1 天）。Wanda Table 7：(input,1) 分组在三种 metric 下都是 8.86——存在 metric 无关的关键输入通道；先保护它们，比在层间搬稀疏度预算更符合证据。
3. **多种子低样本敏感度方差过滤**（~0.5 天）：Wanda 式 1–16 条校准重复采样，方差大的层不再分配。
4. 补 4:8 与 60% 实验点对齐论文表格（~0.5 天）。

### 来自 LLM-Pruner
5. ★**结构保护先验：首 3 层 + 末层禁剪**（~2 小时）。我们的 sgmix 分配图恰把部分首层推到 0.65 上界（layer0 q/k/v/o=0.65），与"首末层最不可剪"的文献共识相反——先验保护应优先于任何敏感度公式。
6. ★**端到端 Taylor 一阶项做敏感度**（~1 天）：`Σ|∂L/∂W · W|` 是真实端到端损失差，天然含层间交叉项——正对 SGMix"逐层可加假设失效、损失非凸"的病根（LLM-Pruner 保留一阶项的理由：校准分布 ≠ 训练分布，梯度不为零）。
7. ★**耦合组约束**（~2–3 天）：Q/K/V 输入维-头-o_proj 必须整组同删同留。未来做头剪枝或 2:4 注意力时不按组决策，会复现论文中 68378 PPL 的断链事故；对 GQA（Qwen2.5 即 GQA）的 KV 头耦合论文未讨论，需自行推导（**未获取**）。
8. **LoRA 恢复臂**（~1–2 天）：rank 8 / lr 1e-4 / 100 warmup / bs 64 / 2 epoch / 全线性层；我们 0.5B 模型预计 <1h，可检验"敏感度不迁移"有多少份额属于缺补偿。

### 来自 Sheared-LLaMA
9. ★**全局 min-max 掩码学习替代启发式分配**（~1–2 周）：把 SGMix 的 `allocate()` 换成 hard-concrete 掩码 + 形状拉格朗日（β=0.83/ζ=1.1/γ=−0.1，LR_z=1.0），用真实损失端到端驱动——结构上不可能犯"可加代理"错误；起步可先只对稀疏度（不做形状）开放自由度。
10. **动态批量加载**（~1 天）：域级指数上升重加权（m=50），只需逐域验证损失，实现极便宜；若我们的校准/评测混多语料，这是比层级再分配更被验证的"再分配"维度。
11. **剪后小预算 CT 消融**（~1 天跑通 + 训练）：文献证明 0.2B token 就把 12.99→7.46；对我们 OBC 0.5B（17.52 vs dense 13.03）值得先测 0.1–0.5B token 的回收曲线。
12. **掩码折叠技巧**（~0.5 天）：非 0/1 掩码值吸收进参数，保证"乘输出的掩码 = 精确删参"，可用于我们的结构化实现。

### SGMix 负结果的书面诊断
结合 `results/20260903_025646_sgmix*.json`：敏感度谱跨约 8 万倍（v_proj 278 → gate_proj 2.2×10⁷），`allocate()` 的反比映射在 α=0.5 下立即打满 [0.4279, 0.65] 双边界、均值只能到 0.4764，分配退化为二值化——动态范围失控是直接死因；深层原因是 OBS 干跑隐含"单权损失可加 + 逐层局部损失 ≈ 端到端 + 剪后激活不变"三个不成立的假设（第 5 节 1/6/9 条各对应一个替代方案）。两次运行（29.53、34.97）均劣于均匀 25.52，与诊断一致。

## 6. 我们 2:4 = 70.14 的文献定位

实测：Qwen2.5-0.5B，Wanda per-output top-k 的 2:4 组内变体，WikiText-2 PPL 70.14（dense 13.21；同实现非结构化 50% = 25.52；magnitude 50% = 485.58）。文献锚点（Wanda 论文 Table 3，LLaMA，WikiText）：2:4 = Magnitude 42.13 / Wanda(无更新) 11.53 / SparseGPT(有更新) 11.00 @7B；9.58/6.25 @13B/65B。

- **绝对数不可直比**（规模、tokenizer、评测口径不同），但**相对退化率**可比：文献 7B dense→2:4 为 ×2.0（5.68→11.53），我们 dense→2:4 为 ×5.3、非结构化→2:4 为 ×2.75（25.52→70.14）。
- 定位：70.14 处于"**无补偿纯排序实现**在小模型上的正常水平"——与文献 magnitude-2:4 同类（7B 上 42.13 是无补偿崩坏的代表）。距文献 Wanda-2:4（无更新 11.53）的差距主要是：(a) **缺权重更新**——文献显示 SparseGPT 补偿在 2:4 下稳定优于无更新（11.00 vs 11.53），`obc.py` 的 `_sequential_zero_dynamic` 加组内 2:4 定秩即可实现 SparseGPT-2:4；(b) **0.5B 级小模型对结构化稀疏的容忍度远低于 7B**——与"小模型更难剪"的文献共识一致但未被单独量化，可作我们的实验贡献点。≤1B 模型的同口径 2:4 PPL 未找到（**未获取**，检索范围限于本次三篇全文）。
