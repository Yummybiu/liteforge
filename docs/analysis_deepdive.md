# 结果二次深挖：人工分析之外的模式

本文是对 `results/` 全部 47 组 JSON 的第二轮数据挖掘，**只报告已知结论（TECHNICAL_REPORT.md 五条主结论 + 决策日志）之外的新模式**。所有数字均可由文中标注的文件与计算方式复算；口径：lossmeter 损失 = tr(ΔW·H·ΔWᵀ)（`lossmeter.py`），"每权重损失" = loss/(d_out·d_in)，NLL 取自各文件 `metrics.nll`（65,504 token 口径）。

---

## 1. 逐层敏感度结构：模块型主导 + 深度单调 + 长尾谱

**数据源**：`losses_qwen0.5B.json`（168 层）、`losses_qwen1.5B.json`（196 层），计算方式：按模块型聚合 w4g128 的每权重损失的几何均值/占比；对 log 每权重损失做方差分解（模块型 7 组 × 深度三分位）。

**(1a) MLP 压倒注意力，但那是"大矩阵效应"**。w4g128 原始损失占比：0.5B 中 gate 43.3% + up 35.6% + down 4.0% = 82.9%，attn 全部仅 17.2%；1.5B 为 88.2% vs 11.8%。按每权重归一后排序反转：down_proj（0.5B 几何均值 5.1e-2）和 o_proj（8.8e-2）反而**最不敏感**，gate/up/q/k 在 0.8–3.3 之间。原始占比 ≈ 参数量占比（gate/up 各 436 万参数 vs q 80 万），即 MLP 的主导地位主要是"它大"，不是"它脆"。

**(1b) 敏感度谱是长尾而非双峰，且方差 73–83% 被两个粗特征解释**。全部 168 层每权重 w4 损失的百分位：p10=3.2e-2、p50=1.53、p90=4.2、max=12.6（0.5B）——跨两个数量级的单峰长尾，top-10% 层持有 32.3%（0.5B）/ 37.7%（1.5B）的总量。方差分解：模块型单独解释 log 方差的 **66.4%（0.5B）/ 49.5%（1.5B）**，加深度三分位后达 **83.3% / 73.5%**。含义：逐层精细分配的"信息上限"本来就只有 ~20–30%，均匀基线天然难打败——这是 SGMix 失败的结构性背景（其直接机理仍是已知结论：OBS 干跑度量不迁移），也说明未来分配器应把表达力花在"模块型×深度"粗规则上而非逐层自由度。

**(1c) 双峰出现在模块内部：v_proj 与 down_proj 的深层尖峰**。0.5B 每权重损失动态范围（max/min）：o_proj **9586 倍**、v_proj **2313 倍**、down_proj 286 倍，而 gate 仅 6.5 倍。top-8 敏感层在两个模型上高度一致地由**深层 v_proj** 垄断：0.5B 的 blocks 20–23 v_proj（9.3–12.6，全模型中位数的 6–8 倍）、1.5B 的 blocks 23–27 v_proj（6.4–10.8）。

**(1d) 深度单调上升**。逐块几何均值：0.5B 末 4 块 / 首 4 块 = **8.06 倍**，1.5B = 3.57 倍——规模越大深度梯度越缓。

**(1e) 未解之谜：1.5B 独有的"早期 MLP 尖峰"**。1.5B 的 blocks 1–2 出现 gate/up 异常敏感（gate 每权重 11.2 / 7.0，为该模型中位数的 8.9/5.6 倍），0.5B 完全没有（其 top gate 全在 19–23 层，max 4.04）。疑似 BOS/前几 token 激活在这几层被放大（文献中"早期层对首 token 超敏感"的现象），本轮数据无法验证机理——标注为待验证假设。

## 2. DP 分配策略：可压缩成"模块型规则 + 深度阈值"，组内完美自洽，跨模型部分可迁移

**数据源**：`alloc_qwen{0.5B,1.5B}_t{2.75,2.5,2.25}_{dp,greedy}.json` 的 `layers` 映射；边际成本 mc(w3→w2) = (L_w3−L_w2)/每权重，与分配结果做分离度检验（AUC）。

**(2a) DP 的解几乎是深度阈值规则，不是逐层自由分配**。0.5B t2.5 下各模块被分到 W2 的 block 集合：v_proj = {0–14}、up_proj = {0–18}、q_proj = {0–3}、gate = {0–2,4,7–15}、down/o = 全部 24 块——除 gate 有 3 处散点外全部是**连续前缀区间**。策略可一句话总结："浅层压满，深层 v/o/down 保护，深层 q/k/gate/up 用 W3"。

**(2b) 组内自洽性：0 反转**。对每个 (模型 × 模块型) 内混合分配的组，检验"W2 组的 mc 是否全部低于 W3 组"：10 个组（两模型 × q/k/v/gate/up）、覆盖 268 个混合决策，**AUC = 1.000（零反例）**。例如 0.5B gate：W2 组 mc 中位 −22.6 vs W3 组 −62.6。DP 不是在"按类型偷懒"，它在类型内部精确按边际成本排序。

**(2c) W4 保护名单 = 敏感度谱的 top**。t2.75 时 DP 用 W4 赎回的层：0.5B = v20/21/22/23 + k9/11/16 + q23（恰为 §1c top-8 名单成员）；1.5B = v23–27 + o27 + down27 + **gate1/2、up1、gate5**（§1e 早期尖峰）。即预算放宽时，DP 的第一笔支出精准买回谱顶端——分配器行为与 lossmeter 谱高度自洽。

**(2d) 可迁移性：敏感度秩迁移强，分配名单迁移弱——但弱得有道理**。共同 blocks 0–23 上逐层 Spearman（0.5B vs 1.5B，每权重 w4）：v **0.879**、o **0.839**、down 0.542、q 0.486、gate 0.390、up 0.199、**k −0.034**。同层分配一致率仅 75.6%（t2.75）/ 71.4%（t2.5）。不一致恰好集中在敏感度最平坦的模块（q/k/gate/up 的 mc 接近、谱平），那里存在大量近优解，分配近乎任意——这也是下述 (2e) greedy≈DP 的同一根源。**结论：可迁移的是"策略规则"（§2a），不可迁移的是逐层名单；k_proj 敏感度完全不可迁移（GQA 小矩阵，且从不被优先）。**

**(2e) 贪心-DP 差距按预算非单调（细化已知结论）**。DP/greedy 预测损失比：t2.25 两模型均**精确相等**（全 W2 是唯一可行解）；t2.5 +0.77%/+0.65%；t2.75 +0.51%/**+5.25%**。已知报告的"1.5B 上 5% 差距"实为 t2.75 单点，不是普遍的规模效应。

## 3. 每比特质量效率：方法族完整排名（新量化）

**数据源**：各 `2026090*_*.json` 的 nll；计算方式：ΔNLL/每权重节省比特（相对 fp16=16 bit；W4g128=4.25、W3g128=3.25、p50=8.0、W4g0≈4.036，均按 `lossmeter.py` 的诚实口径含 scale 开销）。

| 方法（0.5B） | b_eff | PPL | ΔNLL/bit | 1.5B ΔNLL/bit | 3B ΔNLL/bit |
|---|---|---|---|---|---|
| RTN W8g128 | 8.06 | 13.22 | 0.00012 | – | – |
| GPTQ W4g128 | 4.25 | 14.13 | **0.0058** | **0.0057** | **0.0034** |
| RTN W4g128 | 4.25 | 15.69 | 0.0147 | 0.0097 | 0.0099 |
| OBC 动态 50% | 8.00 | 17.52 | 0.0353 | 0.0289 | 0.0253 |
| RTN W4 per-ch | 4.04 | 23.99 | 0.0499 | – | – |
| Wanda 50% | 8.00 | 25.52 | 0.0824 | 0.0456 | 0.0383 |
| RTN W3g128 | 3.25 | 51.37 | 0.1065 | – | – |
| OBC 静态 50% | 8.00 | 54.16 | 0.1764 | – | – |

- **新排名（跨方法族、同比特口径）**：GPTQ W4 ≪ RTN W4 < OBC 动态 50% < Wanda 50% ≈ RTN W3 < OBC 静态。**决策含义：0.5B 上 W4 量化的每比特效率是 50% 非结构化剪枝的 2.4 倍（RTN 口径）～6.1 倍（GPTQ 口径）——预算紧张时应优先量化再剪枝**，此前报告只做了族内比较。

## 4. 校准成本与速度数据重审

**数据源**：`quant_report.duration_s`、`metrics.generate_tokens_per_s`、`spec_*.json`。

**(4a) GPTQ 的"每 PPL 成本"随规模塌方**：校准时长 208.5/467.5/**5510.3 s**（0.5B/1.5B/3B，`024052`/`055219`/`043334`；RTN 仅 0.46/0.63/1.22 s），买回 ΔPPL 1.554/0.468/0.660 → **134 → 999 → 8349 s/PPL（62 倍恶化）**。结合 §3 的每比特效率：GPTQ 的质量收益递减同时成本超线性——3B 上"买质量"性价比最差，但仍是唯一能把 W4 推到距 fp16 仅 0.33 PPL 的方法。

**(4b) 3B 校准超线性部分未解释**：0.5B→1.5B（3.1× 参数）时长仅 2.2×，1.5B→3B（2.06× 参数）却 11.8×。已核对 `deep_batch.log`（03:00:39 加载 → 04:32:47 完成）确认是真实计算非卡死；d_in² 项（down_proj d_in 8960→11008）只能解释 ~3×，**残差 ~4× 未解释**（疑似 fp64 Cholesky/内存压力），标注为待查。

**(4c) generate tok/s 字段在 <1B 模型上是噪声**：0.5B 四个带该字段的运行 tok/s = 13.9（dense）/13.4（wanda）/**16.9（sgmix α=1）**/15.5（sgmix α=0.5）。代码无稀疏内核，剪枝模型不可能快 21%，故 ±12% 为基准噪声地板（3 iter × 128 token 太短）；该字段在 0.5B 上不可用于 <10% 的差异判断。0.5B 与 1.5B dense tok/s 几乎相同（13.9 vs 14.3）也印证生成是启动/框架开销主导而非带宽主导。

**(4d) 投机解码 wall 加速比跨会话不可比（新细节）**：用 speedup = tok/fwd ÷ (1+(k+1)·r) 反解各运行的草稿/目标步时比 r：k4-bf16 = 0.449、k8-bf16 = 0.727、k4-fp32 = 0.184——同 dtype 的 r 漂移 1.6 倍，说明 `speedup_wall`（1.41/0.97/1.96）受会话间基准漂移污染（baseline tok/s 6.3–12.8 不等），**只有 acceptance 与 tok/fwd 是可信量**；已知"k=8 wall<1"在此口径下即 r=0.727 恰好越过该运行的盈亏线 r=(7.314−1)/9=0.70。另外 bf16 翻转把 acceptance 从 0.6985 虚抬到 0.8929（+0.19）、tok/fwd +0.81——方向是向上虚高，fp32 数据才是真实接受率。

## 5. 异常与离群点清单

1. **权重误差反转（新微证据）**：`mean_abs_weight_err` GPTQ 一致地**大于** RTN（0.001939 vs 0.001933；0.002542 vs 0.002534；0.002300 vs 0.002292），但 PPL 三规模全胜——GPTQ 增大原始权重误差、降低 Hessian 加权输出误差，是"激活感知 ≠ 幅度感知"最直接的逐数字证据（幅度失真已知结论的微观落地）。
2. **apply-uniform ≈ gptq-scratch（已解释的巧合）**：`apply_qwen0.5B_t2.5_unifw4` PPL 14.1639 vs `gptq_scratch` 14.1349（差 0.2%；1.5B 差 0.8%）。原因：`allocate.py::apply_allocation` 对量化选项固定用 `impl="gptq"`。推论：**预算批 ρ=1.000 是"menu 按 RTN 口径预测 vs GPTQ 口径实测"的秩相关**——排序对实现口径失配稳健（比已知结论更强的表述）；且 uniform-W4 各预算点实为同一 4.25bpw 模型（三个 alloc 文件 predicted_total_loss 相同），它不满足预算约束，只作质量锚点，阅读预算批表格时勿当作可行方案。
3. **预测→实测的放大指数 ≈ 2**：以同模型 unifW4 为锚，ΔNLL 增幅/预测损失增幅之比取对数得局部指数 β=1.60–2.57（6 个 DP 点，均值 ≈2.1）——**实测损伤随预测损失近似二次增长**（误差复合的定量化）；β 随预算加深而降是 NLL 在 12–13 附近饱和所致（PPL 1e5 量级封顶），全局单指数拟合残差达 4×，不可用。
4. **dense 评测长度敏感性**：0.5B dense 65,504 token PPL 13.2064（`011442`）vs 296,815 token 13.0282（`20260906_051031`），差 −1.35%——**PPL 对比噪声地板 ~1.4%**，小于它的方法间差异（如 0.5B dense 13.21 vs w8 13.22）不显著。
5. **0.5B 第 0 层注意力几乎免费**：block0 o_proj 每权重 w4 损失 1.45e-4（全模型最低，比中位数低 4 个数量级）、v_proj 5.5e-3——首层注意力在任意预算下都应压满/剪掉；DP 也确实给 block0 全部 W2。
6. **菜单单调性零违例**：840/980 次（L_w8≤L_w4≤L_w3≤L_w2，p25≤p50≤p75）全部通过，lossmeter 数值健全，可放心作为分配器输入。
7. **同配置重复运行的确定性**：0.5B GPTQ 两次运行 PPL 逐位一致（14.1349），时长漂移 13%（208.49 vs 182.08 s）——质量确定、时间不确定。
8. **覆盖缺口**：MMLU 仅有 dense 基线（0.476/0.572，n=500），无任何压缩模型的下游对照；`budget15b.log` 中遗留一次 apply 路径 `collect_xtx` NameError 崩溃（历史 bug，现有 apply_*.json 均为修复后产出）。

## 汇总：对下一步的三条直接指引

1. **分配器表达力应止步于"模块型 × 深度段"规则**（§1b 方差上限 73–83%），逐层自由度收益有限；
2. **低预算部署优先量化**：W4 族每比特效率是 50% 剪枝的 2.4–6.1 倍（§3），菜单的低比特选项应用 GPTQ 口径重测（与已知"地板"结论互补）；
3. **先修三件事**：3B GPTQ 时长异常（§4b）、0.5B tok/s 基准时长（§4c）、per-layer α 的 oracle 空间——smooth 数据（`smooth_*.json` per_layer）显示逐层最优 α 散布 0.5–0.8，oracle 相对全局 α=0.7 还能再降 9.0%（0.5B）/14.2%（1.5B）的 W8A8 残差损失，且 up_proj 收益最大（8.5×/平滑后）、down_proj 最小（1.9×）——逐层/逐型 α 是平滑方向最便宜的下一个增益点。
